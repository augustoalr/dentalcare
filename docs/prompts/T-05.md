### 2. Migración SQL idempotente (`supabase/migrations/202611260002_patients_rls.sql`)
Envuelve la migración en `BEGIN; ... COMMIT;`. Debe ser **idempotente** en PostgreSQL 17 / Supabase:

1. **Tabla `public.patients`:**
   - `id uuid PRIMARY KEY DEFAULT gen_random_uuid()`
   - `clinic_id uuid NOT NULL REFERENCES public.clinics(id) ON DELETE RESTRICT`
   - `full_name text NOT NULL CHECK (length(trim(full_name)) > 0 AND length(full_name) <= 120)`
   - `phone text CHECK (phone IS NULL OR (length(trim(phone)) > 0 AND length(phone) <= 32))`
   - `email text CHECK (email IS NULL OR (length(trim(email)) > 0 AND length(email) <= 254))`
   - `date_of_birth date CHECK (date_of_birth IS NULL OR (date_of_birth >= DATE '1900-01-01' AND date_of_birth <= CURRENT_DATE))` *(o validar `<= CURRENT_DATE + 1` para evitar falsos negativos por diferencia horaria UTC vs Dubái/América! Mejor: `date_of_birth >= DATE '1900-01-01' AND date_of_birth <= (CURRENT_DATE + INTERVAL '1 day')::date` para no rechazar nacimientos del día actual en husos UTC+4/+12.)*
   - `medical_alerts text CHECK (medical_alerts IS NULL OR (length(trim(medical_alerts)) > 0 AND length(medical_alerts) <= 1000))`
   - `general_notes text CHECK (general_notes IS NULL OR (length(trim(general_notes)) > 0 AND length(general_notes) <= 2000))`
   - `created_at timestamptz NOT NULL DEFAULT now()`
   - `updated_at timestamptz NOT NULL DEFAULT now()`
   - `deleted_at timestamptz`

2. **Índices para RLS y búsquedas rápidas:**
   - `idx_patients_clinic_id` en `public.patients (clinic_id)`
   - `idx_patients_clinic_active_name` en `public.patients (clinic_id, lower(full_name)) WHERE deleted_at IS NULL`

3. **Triggers (`SECURITY INVOKER` + `SET search_path = ''` + `REVOKE ALL FROM PUBLIC, anon, authenticated`):**
   - `private.guard_patient_update()` (`BEFORE UPDATE ON public.patients FOR EACH ROW`):
     - Bloquea siempre (para cualquier rol) cambios en `id`, `clinic_id` o `created_at` (`RAISE EXCEPTION ... USING ERRCODE = '42501'`).
     - Impide reactivar o modificar un paciente ya archivado si `OLD.deleted_at IS NOT NULL` cuando `current_user IN ('authenticated', 'anon')` (`ERRCODE = '42501'`).
   - `trg_patients_10_guard_update` (`BEFORE UPDATE` → `private.guard_patient_update()`).
   - `trg_patients_20_set_updated_at` (`BEFORE UPDATE` → reutiliza `private.set_updated_at()` ya existente).
   - `private.log_patient_archive()` (`AFTER UPDATE ON public.patients FOR EACH ROW`):
     - Cuando `current_user IN ('authenticated', 'anon') AND (SELECT auth.uid()) IS NOT NULL AND OLD.deleted_at IS NULL AND NEW.deleted_at IS NOT NULL`, inserta atómicamente en `public.audit_log`:
       - `clinic_id = NEW.clinic_id`, `actor_id = (SELECT auth.uid())`, `action = 'patient.archived'`, `entity_type = 'patient'`, `entity_id = NEW.id`, `metadata_json = '{}'::jsonb` (**CERO PII ni datos médicos en `audit_log`** — nunca guardar `full_name`, `phone`, `email` ni `medical_alerts` en `metadata_json`).
   - `trg_patients_30_audit_archive` (`AFTER UPDATE` → `private.log_patient_archive()`).

4. **RLS + `GRANT` mínimos explícitos:**

   - `REVOKE ALL ON public.patients FROM PUBLIC, anon, authenticated;`
