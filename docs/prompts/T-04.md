### 2. Migración SQL atómica de auditoría (`supabase/migrations/202611260001_clinic_settings_audit_trigger.sql`)
Envuelve la migración en `BEGIN; ... COMMIT;` y hazla **idempotente** en PostgreSQL 17 / Supabase:
- Crear función trigger `private.log_clinic_settings_change()` declarada explícitamente con **`SECURITY INVOKER`** y **`SET search_path = ''`** (cualificando `pg_catalog.jsonb_build_object`, `auth.uid()`, `public.audit_log`) y con `REVOKE ALL ON FUNCTION private.log_clinic_settings_change() FROM PUBLIC, anon, authenticated;`:
  - Solo registra cuando `current_user IN ('authenticated', 'anon') AND (SELECT auth.uid()) IS NOT NULL` (evita errores de FK en `actor_id` cuando scripts de seed/migración ejecutan updates como `postgres` sin `auth.uid()`).
  - Comprueba con `IS DISTINCT FROM` si cambió al menos una de las 7 columnas configurables: `name`, `currency_code`, `currency_symbol`, `tax_rate_bps`, `tax_label`, `timezone`, `default_locale`. Si no cambió ninguna (update sin cambios reales), retorna `NEW` sin insertar ruido en `audit_log`.
  - Si cambió al menos una columna, inserta en `public.audit_log` dentro de la **misma transacción**:
    - `clinic_id = NEW.id`
    - `actor_id = (SELECT auth.uid())`
    - `action = 'clinic.settings_updated'`
    - `entity_type = 'clinic'`
    - `entity_id = NEW.id`
    - `metadata_json = pg_catalog.jsonb_build_object('before', ..., 'after', ...)` conteniendo únicamente las 7 columnas de configuración de clínica (cero PII ni datos clínicos).
  - Asociar con `CREATE OR REPLACE TRIGGER trg_clinics_30_audit_settings AFTER UPDATE ON public.clinics FOR EACH ROW EXECUTE FUNCTION private.log_clinic_settings_change();`.
- **Por qué a nivel de BD:** garantiza atomicidad total (si falla el registro de auditoría, el `UPDATE` en `clinics` hace rollback) y evita que una llamada directa a la API modifique la clínica sin dejar rastro en `audit_log`. Por tanto, el frontend **NO** debe llamar manualmente a `appendAuditLog` tras `updateClinicSettings` (evitando entradas duplicadas).
- Documentar el rollback seguro de esta migración en `supabase/README.md` (regla R-18).

### 3. Dominio puro de dinero, impuestos y validación (`src/domain/money.ts`) — sin React ni Supabase
Crear funciones puras, inmutables y sin errores de coma flotante:
- Tipos:
  - `CurrencyDisplayConfig`: `{ readonly currencyCode: string; readonly currencySymbol: string }`
  - `ClinicSettingsInput`: `{ readonly name: string; readonly currencyCode: string; readonly currencySymbol: string; readonly taxRateBps: number; readonly taxLabel: string; readonly timezone: string; readonly defaultLocale: SupportedLocale }`
  - `ClinicSettingsPreset`: presets rápidos multi-país inmutables (`UAE` → `AED`, `AED`, `500` bps, `VAT`, `Asia/Dubai`, `en`; `Spain` → `EUR`, `€`, `2100` bps, `IVA`, `Europe/Madrid`, `es`; `United States` → `USD`, `$`, `0` bps, `Tax`, `America/New_York`, `en`).
- Funciones obligatorias (cubiertas exhaustivamente en `src/domain/money.test.ts`):
  1. `formatMoney(amountCents: number, config: CurrencyDisplayConfig, locale: SupportedLocale): string`:
     - Valida que `amountCents` sea un entero seguro (`Number.isSafeInteger(amountCents)`, lanzando `RangeError` si no lo es).
     - Separa parte entera y céntimos con aritmética entera exacta (`Math.abs` + división entera y `% 100`, nunca `amountCents / 100` con drift en importes grandes) y formatea separadores de miles/decimales según `locale` (`en` → `1,250.00`, `es` → `1.250,00`), anteponiendo el signo `-` en negativos y combinando con `currencySymbol` de forma clara y consistente (p. ej. `AED 1,250.00`, `€1.250,00` o `1.250,00 €`, `$1,250.00` — probado explícitamente con **AED (5%)**, **EUR (21%)** y **USD (0%)** en `en` y `es`).
  2. `calculateTaxCents(subtotalCents: number, taxRateBps: number): number`:
     - Valida enteros seguros (`subtotalCents` entero seguro, `taxRateBps` entero `0..10000`).
     - Usa `BigInt` con redondeo exacto *half-up* simétrico para calcular el impuesto al céntimo exacto sin coma flotante (`(BigInt(absSubtotal) * BigInt(taxRateBps) + 5000n) / 10000n`).
  3. `calculateTaxSummaryCents(subtotalCents: number, taxRateBps: number)`: retorna objeto congelado `{ subtotalCents, taxCents, totalCents }`.
  4. `percentStringToBps(rawPercent: string): number | null` y `bpsToPercentString(taxRateBps: number): string`:
     - Parsea texto decimal (`"5"`, `"5.00"`, `"21"`, `"0"`, `"7.5"`, `"7,5"`, `"100"`) mediante expresión regular y aritmética entera pura (jamás `parseFloat(x) * 100`), devolviendo `null` si está vacío, es negativo, supera `100`, tiene más de 2 decimales o contiene caracteres inválidos.
     - `bpsToPercentString(500)` → `"5"`, `bpsToPercentString(525)` → `"5.25"`, `bpsToPercentString(0)` → `"0"`.
  5. `validateClinicSettings(raw)` — validación pura alineada 1:1 con los `CHECK` de PostgreSQL (`name` no vacío ≤ 120 chars, `currencyCode` normalizado a mayúsculas `^[A-Z]{3}$`, `currencySymbol` no vacío ≤ 10 chars, `taxRateBps` entero `0..10000`, `taxLabel` no vacío ≤ 20 chars, `timezone` no vacío ≤ 64 chars, `defaultLocale` `'en' | 'es'`), devolviendo códigos de error tipados (sin textos hardcodeados).
