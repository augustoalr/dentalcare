## Requisitos técnicos y de arquitectura
1. **Rama y commits:**
   - Crea la rama `t-01-esqueleto-frontend` desde `main` actualizado (`git pull origin main`).
   - Usa Conventional Commits (`feat(T-01): …`, `test(T-01): …`, `docs(T-01): …`, `chore(T-01): …`).

2. **Separación de responsabilidades (SoC) y estructura real (`docs/ARQUITECTURA.md`):**
   - `src/domain/` — Lógica pura sin imports de React ni APIs del navegador (por ejemplo: tipos y utilidades puras de `locale` como `SupportedLocale = 'en' | 'es'`, normalización y fallback de idioma).
   - `src/services/` — Wrappers/adaptadores aislados (por ejemplo: wrapper ligero de almacenamiento local `IStorageAdapter` / `BrowserStorageAdapter` para guardar la preferencia de idioma de forma segura y testeable, sin usar `localStorage` suelto por la UI).
   - `src/i18n/` — Archivos de traducción `locales/en.json` y `locales/es.json`, contexto/hook de traducción tipado y sin claves sueltas. **Cero textos visibles hardcodeados en JSX** (regla R-14).
   - `src/ui/` — Sistema de diseño atómico:
     - Tokens semánticos CSS (colores de superficie, texto, primario, secundario, borde, éxito, aviso, peligro y **alerta médica crítica** con contraste WCAG AA: p. ej. `--medical-alert`, `--medical-alert-bg`, `--medical-alert-border`, `--medical-alert-foreground`) conectados a Tailwind CSS (sin colores hex ni medidas arbitrarias sueltas en los componentes).
     - Utilidad `cn` (`clsx` + `tailwind-merge`) y base de `shadcn/ui` (`components.json` + primitivos necesarios como `Button`, `Card`, `Badge`).
     - Componentes base reutilizables de estados visuales:
       - `LoadingState` (estado de carga accesible con `role="status"`).
       - `ErrorState` (estado de error con mensaje claro y acción opcional de reintentar).
       - `EmptyState` (estado vacío con icono, título, descripción y acción opcional).
       - `MedicalAlertBanner` (alerta médica crítica usando los tokens semánticos rojos + icono de `lucide-react`, nunca solo color, cumpliendo `docs/PRUEBAS.md`).
     - Manejo limpio de desbordamiento (`overflow`/truncado o ajuste seguro) en textos largos.
   - `src/features/welcome/` — Pantalla de bienvenida responsive móvil-primero para DentalCare:
     - Selector funcional de idioma **EN / ES** (persistido mediante el wrapper de `src/services/` y sincronizando `document.documentElement.lang`).
     - Diseño limpio, profesional y sanitario que presente DentalCare, indique que el entorno es de pruebas con datos sintéticos (R-10) y muestre de forma ordenada el selector EN/ES y el sistema visual base (sin nombres técnicos internos ni datos ficticios de pacientes reales, R-14).
3. **PWA manifest:**
